## 已修复并验证

1. 认证会话
   - HttpOnly 哈希 Cookie 可用于 session check
   - Cookie 鉴权的写请求要求 CSRF header
   - 原始 token 不再写入 localStorage
   - URL token 会在应用入口同步到内存并从地址栏移除

2. 订阅节点数据一致性
   - 清空纯手动订阅的最后一个节点后，`raw_nodes` 会同步清空
   - 手动订阅刷新只重算本地节点，不请求 `manual://nodes`
   - 复杂手动节点的嵌套 YAML 字段可保留

3. API 契约与输入边界
   - 单订阅导出不存在的订阅时返回 404
   - 规则和规则分类 batch API 使用 Pydantic schema，非法 ID 返回 422
   - JSON 响应体格式错误时，前端保留原始正文而不抛出 JSON 解析异常

4. SSRF 防护
   - URL 主机名校验会连续解析两次 DNS 并合并结果，第二次出现私网地址时拒绝请求

5. 迁移与运行态
   - 增加 Alembic revision `8f5c2d1a7b90`，补齐 `subscriptions.enabled` 和 `subscriptions.node_renames`
   - 在隔离 SQLite 上验证 upgrade 和 downgrade
   - 增加 `/ready` 数据库就绪检查，Docker healthcheck 使用该端点

6. 工程质量
   - Python runtime 和 dev 依赖拆分，直接依赖固定到已验证版本
   - Docker runtime 不再安装 pytest 和 pytest-asyncio
   - 前端增加正式 `test`、`typecheck` 脚本
   - npm 依赖升级并将 lockfile 的 HTTP 镜像地址改为 HTTPS 官方 registry
   - Dockerfile 增加非 root 运行、无缓冲日志和 healthcheck 验证路径
   - 新增 Playwright E2E，以真实 Chromium 用户事件验证手动节点完整编辑链路
   - CI 新增完整 Git history 的 Gitleaks redacted 扫描和隔离容器 E2E

7. 手动节点编辑预览
   - 修复手动节点存在但无上游 `source_nodes` 时，前端回退已物化 `raw_nodes` 并再次合并原始节点，造成预览重复及重复前缀的问题
   - E2E 先复现“预览应为 1 个节点、实际为 2 个”的失败，再以原始 `manual_nodes` 作为候选源修复
