## 2. 显式冲突深度辨析 (Explicit Conflicts Breakdown)

针对审计中暴露出的历史约束与主干规范/实机现状之间的矛盾，本注册表明确登记以下显式冲突，绝不通过模糊合并逃避问题：

1. **敏感凭据存储模型冲突 (Node Plaintext vs Historical Vault)**：
   - *历史旧约束*：早期规范（如 Schema 000001-000010、凭据引用修补）要求使用 `node_credentials` 表、AES-GCM AEAD 加密、CAS 版本号及 Vault 存储。
   - *主干与用户原话*：`csp-debloat-over-engineering` 与本 Living Spec（`FR-AUTH-03` / `FR-INV-06`）遵照用户亲口指示“明文直存，不引入多余加密库”，在 `nodes` 表明文持久化 `server`、`port`、`credentials`，前端提供明文 CoW 覆写抽屉。
   - *裁定处置*：确立明文直接持久化为主干标准，标记历史加密相关条款为历史淘汰冲突。

2. **探测调度周期模型冲突 (1-Minute Sweep vs Historical 10-Minute Polling)**：
   - *历史旧约束*：历史部分规范（如 `HR-098`）设定固定 10 分钟单一定时器探测节点。
   - *主干与用户原话*：主干 `FR-PROB-02` 按照用户指令重构为分层解耦模型：1 分钟协调器扫描、5 分钟失败冷却、1 小时调度周期、24 小时观测时效。
   - *裁定处置*：10 分钟单一轮询已由分层模型覆写，历史 10 分钟条款标记为显式覆写冲突。

3. **策略组双模式解包能力缺失冲突 (Policy Group Dual-Mode & Unpack Gap)**：
   - *历史与用户原话*：用户原话明确指示“直接组引用”与“解包获得叶节点”均为核心特性；历史多项规范均包含解包叶节点。
   - *实机实现事实*：Go 后端目前仅实现直接组引用，解包叶节点（Unpack / Flatten Leaf Nodes）完全缺失（`AllNodeLogicalIDs` 仅为 DAG 空组检测，未展开成员）。
   - *裁定处置*：客观判定为不符合（`FR-POL-02`），归入业务未决问题组 1 待用户选择去重与循环保护规则后落地。

4. **策略组成员混合交错顺序缺陷冲突 (Mixed Interleaved Order Bug)**：
   - *历史与业务需求*：管理员在 UI 中编排节点与子组的交错顺序（如 `[节点A, 子组B, 节点C]`）。
   - *实机实现事实*：图解析器（`internal/resolver/graph.go:140-185`）硬编码先遍历显式节点、后遍历子组，破坏了相对交错顺序。
   - *裁定处置*：明确此为实现缺陷而非等价设计，归入问题组 2 待用户决策是否需要严格交错保序。

5. **纯节点导出目标空组强校验冲突 (Pure-Node Export vs Empty-Group Validation)**：
   - *业务语义*：Sing-box / Surge / Quantumult X 为纯节点协议，不导出策略组。
   - *实机实现事实*：顶层 `validate()` 无条件对所有目标校验空组，导致未决空组阻断纯节点导出。
   - *裁定处置*：归入问题组 4 待用户决策纯节点目标是否跳过策略组校验。

6. **前端本地视口饥饿与服务端分页联动冲突 (Viewport Starvation vs Server Pagination)**：
   - *历史规范*：历史前端通过 `checkViewportStarvation` 在本地最多发起 3 步翻页补足视口。
   - *主干规范*：服务端全量筛选与分页已冻结为标准架构，本地 3 步翻页为已知缺口，待用户确认跨页选择边界（问题组 6）。
