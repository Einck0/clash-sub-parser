## 1. 来源分级体系定义

为了根除历史开发中“将提案草稿的问题描述误当成用户原话”、“将推测当成硬约束”的治理缺陷，本工程建立四级证据确权体系：

| 等级标识 | 等级名称 | 定义与准入标准 | 法律效力与优先级 |
|---|---|---|---|
| **TIER-1: USER-VERBATIM** | **用户明确原话** | 仅限用户在会话交互中亲口发出的明确指令、确认与决策，具有不可动摇的最高效力。必须附带原始会话记录凭据。 | **最高**（高于一切历史文档与代码实现） |
| **TIER-2: HISTORICAL-CONTRACT** | **历史变更契约** | 历史上由主脑/规划机经评审立项的 26 个 OpenSpec 变更集（`openspec/changes/*`）中的正式规范（`spec.md`）。**注意：变更提案（`proposal.md`）中的“Why”问题描述属于规划者分析，不得作为用户原话引用**。 | **高**（作为系统既有能力基线） |
| **TIER-3: IMPLEMENTATION** | **当前实机实现事实** | 以代码库真实文件（Go、Vue、SQL、Shell）在 HEAD `1c5a604` 的实际代码行与测试退出码为依据。反映系统客观现状，但不自动证明其设计正确。 | **中**（用于审计符合度，不代表理想规范） |
| **TIER-4: EXPERIENCE** | **开发者与工程经验** | 记录在根目录 `.exp.md` 中的历史排障、调试手记与开发规范。仅作背景与工程方法参考，不可推翻高等级约束。 | **辅助参考** |

## 2. 核心条款来源确权清单

### 2.1 用户明确条款 (TIER-1: USER-VERBATIM)

以下条款经过严格甄别，确认为用户亲口确认的核心诉求：

1. **核心需求重写与模糊澄清要求**：
   - *用户原话*：“按你的建议来，重写当前的SPC，再根据规格看当前是否符合，模糊整合询问我，然后再落地”。
   - *落地映射*：确立当前阶段为纯文档特性包阶段，编写 Living Spec、符合度矩阵、<=6 组问题清单，并经由用户确认后再开展业务代码施工。
2. **策略组双模式支持（直接引用 + 解包展开）**：
   - *用户原话*：“直接将其他策略组作为节点引用”与“解包获得其中节点”均为必需的核心特性。
   - *落地映射*：`FR-POL-01`（直接引用）与 `FR-POL-02`（解包展开），两者并列为主干核心需求。
3. **管理端与导出链接独立鉴权开关但复用统一令牌**：
   - *用户明确诉求*：管理端鉴权与导出链接鉴权开关相互独立（分别受控），但可共用同一套统一系统令牌；且导出端点支持免密公开拉取。
   - *落地映射*：`FR-AUTH-01`、`FR-AUTH-02`、`FR-PUB-04`、`FR-PUB-05`。
4. **明文敏感字段存储与人工覆写要求**：
   - *用户明确诉求*：订阅来源 URL 与节点连接参数直接采用明文存储，并在前端抽屉提供直接修改（CoW 覆写）能力，不引入多余的复杂加密 Vault 或过渡 Shim。
   - *落地映射*：`FR-AUTH-03`、`FR-INV-06`。
5. **订阅抓取失败时节点必须保全**：
   - *用户明确诉求*：当订阅远端抓取失败或返回 0 个有效节点时，严禁清空本地既有资产，必须全量保留存量节点与来源关联。
   - *落地映射*：`FR-INV-02`。
6. **废除机械像素硬约束**：
   - *用户明确诉求*：否决静态 44px 等盲目固定像素门禁，以真实视口交互可用性与无遮挡为验收标准。
   - *落地映射*：`FR-UI-01`。

### 2.2 澄清与纠偏事项（不得作为用户原话的辨析）

1. **提案背景描述（Why/Problem）辨析**：
   - *纠偏*：`openspec/changes/*/proposal.md` 中出现的“生产 SQLite 数据库 404”、“历史 Python 逻辑行为”、“用户反馈全周期突发全量检测冲击”属于当时编排者的提案背景分析，不是用户 verbatim 文本。在 Living Spec 中统一归类为 `TIER-2: HISTORICAL-CONTRACT`。
2. **安全风险警示与业务决策边界**：
   - *纠偏*：安全审计指出“明文存储 Token 和 Secret 存在泄漏风险”，此项属于工程安全警示与最佳实践建议，**不能擅自推翻用户明确要求的明文存储实现**。规格中保留明文事实，并注明安全警示与生产网络隔离要求。
3. **探针周期各层参数属性**：
   - *纠偏*：历史讨论曾质疑“1m 协调器扫描、5m 失败冷却、1h 调度周期、24h 观测有效期是否存在冲突”。实机审查证实四者属于不同生命周期层级，不构成矛盾，不得作为未决问题反复骚扰用户。
4. **抓取自动重试属性**：
   - *纠偏*：当前订阅服务缺乏自动重试循环。由于用户未曾提出必须支持自动重试，该项不得标记为“用户报告的缺陷”，而应客观标记为“现状未实现 / 待确认”。
