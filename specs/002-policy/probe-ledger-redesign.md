## 业务职责（冻结决策）

### US-R1 / FR-R1 统一节点工作台（P1）
- `/nodes` 是唯一节点与探测操作入口；取消独立「探针引擎」导航与 ProbesView 页面。旧 `/probes` 只做路由重定向 `/nodes`，不保留第二套逻辑；更新首页入口、历史 tab 读取和多设备导航。
- 日常流程：按名称/来源/协议/可用状态查节点 → 选择本页或跨页保留的明确 logical_id → 手动检测 → 原位看排队/进行/结果与最近探测时间 → 需要时打开运行明细和有界批次历史。未选中时不得默默变成全库检测；全量检测必须独立明确按钮、范围提示与确认。
- 列表桌面紧凑行、移动精简卡片，筛选和分页变化不造成选错节点。选择计数以实际 ID 集合为准，刷新删除后清除失效 ID。持续刷新仅在可见且有运行时发生，卸载清理；失败保留已加载事实、展示错误与重试，不假报 0。
- 可用/不可用/未测试是主健康三态；排队/检测中是操作态，不替换健康事实。连接版本变更使旧观测不适用于新连接；单次超时/失败给真实原因，不重引入时效/待复核状态。
- 手动检测种类使用全局默认，可在此次操作选择已有检测项；不在节点工作台持久化周期、超时、引擎开关。批次历史沿用保留 100 上限，无扩张性历史系统。

### US-R2 / FR-R2 全局探针配置（P1）
- Settings 增加清晰「探针」分区，统一管理自动探测总开关、默认周期（60..604800 秒）、检测项目和现有超时（1..30 秒）。沿用 `/probes/schedule` 与 Settings API 的领域归属，但界面只在全局配置中编辑；不复制两份状态。
- 总开关仅控制自动任务；关闭时手动检测仍可用。保存后从服务端回读，错误必须可见。无凭据、全局禁用、无可用来源和无到期节点分别解释，不伪造成功。
- 此次不新增引擎核心、网络目标、并发热调优、探测时效可配置项；复用现有执行器、租约、连接版本和失败冷却。

### US-R3 / FR-R3 每订阅源独立探测周期（P1）
- 订阅配置使用 `config.probe_policy` 单一字段，结构为 `{mode: inherit|disabled|custom, interval_seconds?: number}`；新增默认继承。`custom` 要求 60..604800，其他模式不使用自定义周期。省略字段保留已有配置，禁止部分更新丢失重命名/过滤/其他配置。
- 所有模式受全局自动开关约束。来源停用/探测 disabled 不参与自动探测；继承用全局周期，自定义用自身周期。订阅拉取周期与探测周期独立呈现，不互相覆写。
- 同一 logical_id 多来源去重：仅启用且允许探测的来源参与，采用最短有效周期，按 node/kind 仅排一次；有来源但全部停测的节点不参与自动检测。手动确认且无有效订阅来源的节点继承全局周期；普通孤立节点不因此复活。
- 到期按最新对应 kind、对应 connection_revision 的观测时间计算；没有观测/连接版本更新应到期；显式手动操作不受来源周期限制。不另起每源 goroutine/定时器或扫描器，复用统一协调器。
- 升级对未配置源保留当前全局行为，不用遗留且未生效的 AutoTest 字段猜用户停测意图；旧未使用控件退出 UI。无需为 JSON 字段强加数据库表/重复配置。

### US-R4 / FR-R4 策略树筛选业务重做（P1）
- 不再把筛选、手选节点、动态匹配混为一谈。编辑按「候选范围 → 添加成员 → 排除成员 → 实时结果」组织，使用清晰的来源、协议、名称包含/不含/正则、探测状态/延迟字段；同一筛选条件集合为 AND，多条添加来源为顺序并集去重，排除操作按原有明确顺序执行。
- 候选范围明确标注「继承全局筛选 / 使用全部准入节点」；WARP 已有非继承值保持。关闭继承只绕过全局软筛选，不能绕过禁用订阅、准入规则、风险硬约束或凭据校验。节点页搜索不修改任何策略条件。
- 全局筛选和组内条件共用结构化筛选编辑与服务端验证语义，清空条件就是不额外筛选；不得偷偷添加默认健康条件。正则保留现有大小写不敏感、lookaround 和有界超时能力，错误显示原条件，不改写用户表达式。
- 动态条件保持动态：来源/正则筛选未来随订阅刷新重新解析，不能把预览列表保存成静态 ID。手动节点、保留子组引用、展开子组节点、内置动作分开选择且解释；删除所选只删除对应项，不清空其他动态来源。
- 对既有复杂有序 add/remove 源必须无损显示与编辑（可在高级来源区逐条呈现），不强行排序成另一套语义、不丢未知属性。本次不引入地域字段、OR DSL、第二套持久化筛选结构或 shim。
- 修复 remove-filter 用错 globalAdmittedMap 的不一致：使用该组实际候选范围（包括继承豁免）及同一证据上下文。父组引用非继承子组已有穿透能力保持；有条件的子组投影仍保持节点及 builtins 语义。
- preview、validate、export 在实际服务走同一 ConsistentFacts/inputProvider 和 resolver。缺少事实/证据加载错误不能静默改用空库存或当全部通过。基于同一事实时成员 ID/计数一致；预览请求加防抖和代次保护，旧响应不得覆盖新草稿。
- UI 显示候选数/实际成员数及排除原因摘要；普通软过滤是正常筛选，不报拓扑警告；真正空组/循环/不存在引用仍如实阻断。不顺便重写分流规则和准入规则业务。

## 验收与非功能门禁

- 真实后端隔离预览（动态 loopback 临时端口、独立 SQLite、无生产凭据或订阅外联）；使用合成节点、来源与观测构造可重放业务场景。构建与 Go/Vitest/typecheck 只在容器，禁止宿主重型编译。

- Go 全量和前端全量（有环境阻断则记录精确失败），独立 reviewer 对最终合并源码审查后，再对真实预览做桌面/移动视口 critic（含脏 token、加载失败、取消/空态/分页选择）；contract 默认 critic=false 的理由为未知预览，本任务 UI 实际适用，主脑追加质检而非跳过。
- 不要求物理屏幕或手机硬件操作；Playwright 移动视口不得宣称手机实屏通过。无预览则质检未通过，不假绿。
- 所有既有工作树改动保护，逐文件提交，仅 dev，不推 main/新远端分支。生产不部署；预览由准备者负责清理，交付必须说明状态。
