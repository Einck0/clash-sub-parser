## Refined detector contract

1. Retain one anonymous GET to `https://claude.ai/cdn-cgi/trace` using the caller's node-bound client. The final response must retain that HTTPS origin and exact trace path. A foreign origin, login or other path is `restricted/unexpected_redirect`, not trace-region evidence. No timeout, retry, proxy identity or request-selection policy changes.
2. Preserve HTTP denial (`403/451` => `restricted/access_restricted`), rate limiting (`429` => `restricted/rate_limited`) and unexpected-status error handling. On HTTP 200, inspect a **complete bounded response** through the existing generic detector limit of 256 KiB plus one overflow byte. Exactly-boundary late evidence remains valid. Overflow yields `error/response_body_too_large` with no positive region/scope. This deliberately generous trace bound is an engineering resource limit, not an official maximum. No early-marker positive path is allowed.
3. Typed read failure takes precedence over body markers, challenge headers and region assertions: cancellation/budget => `skipped` with the existing typed reason; deadline/socket timeout/read/transport failures => their existing `error` reason. Overflow/read failure never becomes success because an earlier prefix was valid.
4. Cloudflare's official `cf-mitigated: challenge` response header is explicit challenge evidence. Recognized HTML challenge markers (`challenge-platform`, `cf-chl-`, `Just a moment` title) in markup lines also produce `restricted/challenge_or_login`; arbitrary text echoed in a trace field such as `uag=` does not alone establish a challenge. Generic HTML, including a separate apparent loc line inside HTML, is not trace evidence and produces `error/trace_loc_missing`. This is a bounded heuristic, not a complete HTML/challenge-page classifier.
5. Recognize only exact line fields starting `loc=`. LF/CRLF and a final line without a newline are accepted; do not trim/uppercase/repair country values. Each recognized value must be exactly two uppercase ASCII letters and a known matching alpha-2 code in the existing country library. All recognized fields must agree. Unrelated fields, including UA values containing `loc=`, do not count. Identical duplicate loc fields are acceptable.
6. Region failure precedence is: any syntactically malformed recognized field => `error/trace_loc_malformed`; otherwise any unknown/mismapped alpha-2 code => `error/unknown_region_code`; otherwise distinct countries => `error/conflicting_region_markers`; no recognized loc field => `error/trace_loc_missing`. These outcomes carry no positive region, source, scope or unlocked assertion. Preserve the existing blacklist, `available/unlocked/claude_available` and `restricted/banned/sanctioned_region` tuples for valid evidence.
7. Valid region evidence remains `region_source=cdn_trace`, `evidence_scope=cdn_trace`. Summaries explicitly limit the result to CDN trace region and state that account/chat eligibility is unverified; neither a permitted trace country nor HTTP 200 proves account eligibility, paid access, model access or successful chat. Existing same-run exit-country mismatch handling remains `abnormal/region_mismatch`, retaining both countries. No historical row is relabelled.
